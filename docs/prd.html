01产品定位

给已经懂规则、想把翻前打对的玩家，一个能随时掏出手机练 3 分钟的范围训练器。

核心价值

  • 场景化而非背表。不是给你一张 13×13 的图让你背，而是把你放在牌桌上：UTG，手上 8♦2♦，前面全弃牌，你怎么办。
  • 即时对错 + 频率真相。每手牌都能立刻知道 GTO 的动作分布，混合策略的手牌会告诉你 Raise 60% / Fold 40%，而不是简单的对错。
  • 可量化的进步。每个位置每种场景独立累计正确率，错的牌进错题本，弱点在 13×13 热力图上一眼可见。

目标用户

玩过一段时间线上或线下 NLHE、知道位置和 3bet 是什么、但翻前打法凭感觉的中低级别玩家。不面向零基础教学。

明确不做（v1）

  • 翻后（flop / turn / river）训练。
  • MTT / 短筹码 / ICM / 带 ante 的结构。
  • 多人跟注后的挤压（squeeze）与冷 4bet 之外的复杂多路线。
  • 账号系统与云同步，数据只存在本机。

02牌局假设与术语

范围数据只在一套固定假设下成立，这套假设必须先钉死。

项目取值说明
桌型6-max位置顺序 UTG · HJ · CO · BTN · SB · BB
有效筹码100 BB所有场景统一
盲注结构0.5 / 1，无 ante不考虑 straddle
抽水低抽水现金局范围据此偏松，见下方说明
开池尺度2.5 BBUTG / HJ / CO / BTN 统一
SB 开池3.0 BB 或 跛入 1.0 BB加注与跛入的混合体系
BB 应对跛入隔离加注 4.0 BBSB 跛入后 BB 的加注 / 过牌决策
3bet 尺度有位置 3×，无位置 4×例：BTN vs CO 开池 = 7.5 BB；BB vs CO = 10 BB
4bet 尺度有位置 2.2×，无位置 2.5×基于对手的 3bet 金额
关于抽水与范围松紧

抽水从底池里抽，惩罚的是赢小底池、靠翻后做牌的投机手牌，同花 A 因为阻断牌和坚果潜力基本不受影响。本数据集按低抽水条件书写，因此小对子、同花连张、单张间隔同花的开池频率高于常见的低级别抽水局图表。以 HJ 为例，本数据集开池 23.2%，市面上按抽水调整过的图表通常是 19% 到 20%，差额几乎全部落在 22、33、K8s、T8s、97s、86s 与 76s 一类手牌上。若日后要改按中等抽水训练，调整集中在这几类牌，不影响数据结构。

三个反复出现的词

  • 169 手牌：所有起手牌按同花 / 非同花 / 对子归并后的等价类，正是那张 13×13 的表。
  • 组合数（combo）：对子 6 组，同花 4 组，非同花 12 组，合计 1326。抽牌频率按组合数加权，训练分布才等于真实牌桌分布。
  • 混合频率：GTO 对某些手牌给出的是概率而非唯一动作，例如 UTG 的 A8s 加注 50%、弃牌 50%。

03场景矩阵

一个「场景」= 英雄位置 + 面临的动作。每个场景对应一套独立的范围数据，共 36 套，全部进入第一版。

类别英雄面临可选动作场景数
Open Raise前面全部弃牌Raise / Call（跛入）/ Fold5
3 Bet前面一人开池，无跟注Raise（3bet）/ Call / Fold15
4 Bet英雄开池后被 3betRaise（4bet）/ Call / Fold15
vs LimpSB 跛入，英雄在 BBRaise（隔离）/ Check1

展开

  • Open Raise（5）：UTG、HJ、CO、BTN、SB。BB 无此场景。
  • 3 Bet（15）：HJ 面对 UTG；CO 面对 2 个位置；BTN 面对 3 个；SB 面对 4 个；BB 面对 5 个。
  • 4 Bet（15）：UTG 被 5 个位置 3bet；HJ 被 4 个；CO 被 3 个；BTN 被 2 个；SB 被 BB 3bet。
  • vs Limp（1）：BB 面对 SB 跛入。
关于 Call 按钮与 SB 跛入

原型图在 Open Raise 场景保留了 Call 1BB（即跛入）。UTG 至 BTN 四个位置的跛入频率恒为 0，选它一律判错，它是一个真实的诱惑项。SB 是唯一例外：按已确认的混合体系，SB 的跛入是有正频率的正解动作，它的范围表因此有三种颜色，判定同样走频率阈值规则。BB 面对跛入的应对独立成一个场景。

子场景的进入方式

首页按英雄位置聚合成一张卡（与原型一致）。点进 3 Bet 的 BTN 卡后，先出一层子场景选择：vs UTG / vs HJ / vs CO / 混合练习。混合练习按各子场景等权随机，用于考试式复习。Open Raise 卡无子场景，直接开练。

04范围数据模型

每套范围 = 169 个格子 × 每格一个动作频率分布。这是整个 App 唯一的真相来源。

{
  "id": "3bet.btn.vs_co",
  "hero": "BTN",
  "vs": "CO",
  "facing": { "action": "open", "size": 2.5 },
  "sizing": { "raise": 7.5, "call": 2.5 },
  "actions": ["raise", "call", "fold"],
  "grid": {
    "AKs": [100, 0, 0],
    "A5s": [ 75, 25, 0],
    "KTs": [ 25, 75, 0],
    "72o": [  0, 0, 100]
  }
}

频率以整数百分比存储，三者之和恒等于 100。构建时用脚本校验：每格求和、每套范围的总入池率（VPIP）落在合理区间、频率只取 12.5 的倍数以避免噪声。

05判定与评分

混合策略下不存在唯一正确答案，判定规则必须写死在文档里。

单手牌判定

  • 玩家所选动作的 GTO 频率 ≥ 30% 判为正确，否则判错。
  • 纯策略格子（某动作 100%）退化为唯一正确答案，与直觉一致。
  • 频率在 1% 到 29% 之间的选择判错，但结算页标注为「可接受的低频选择」，与硬错误区分显示。
  • 阈值可在设置里调成 严格 = 只认最高频动作 或 宽松 = ≥ 15%。

一局 20 手

默认每次训练 20 手（原型的 1 / 20），可设为 10 / 20 / 50。抽牌采用分层抽样：60% 来自非纯弃牌区，40% 来自纯弃牌区，避免整局都在按 Fold。同一局内不重复同一手牌。

得分评级含义
20 / 20Perfect该场景可以进入下一个位置
18 – 19Excellent只差边缘手牌
15 – 17Good主体正确，边界模糊
12 – 14Fair建议先看一遍 Table 再练
< 12Needs Work范围尚未建立

反馈时机

两种模式，设置里切换。考试模式（默认，与原型一致）：全程不提示，20 手打完在结算页一次性复盘。教学模式：每手牌选完立刻弹出正确动作与频率条，点任意处继续。

06功能规格

五个主界面，加两个辅助面。

6.1 首页

  • 按 Open Raise / 3 Bet / 4 Bet 三段分组，每段内按位置排成两列卡片。
  • 每张卡显示：位置名、累计手数、累计正确数、累计错误数（与原型一致），底部一条正确率进度条。
  • 未练过的卡显示 0 / 0，视觉上降透明度，与已练过的卡区分。
  • 顶部右侧 ? 打开说明页；顶部左侧新增总览入口，进入统计面。

6.2 场景面：先看表，再开练

点首页任一张卡，不直接进牌桌，而是先弹出该场景的详情面。自上而下是：场景名与对手位置切换、该场景的累计战绩、完整 13×13 范围表、图例，最底下才是 Start Training 按钮。

这一步的价值在于把「看表」和「练表」拆成两个动作。训练前扫一眼范围，训练中就不必再调表；想纯看表复习时也不用被迫开一局。3 Bet 与 4 Bet 的对手位置在这一面用横向标签切换，切换后战绩与范围表同步更新，另有一个混合标签，随机抽取该位置的全部子场景。

6.3 牌桌训练面

  • 六人桌俯视图，英雄固定坐底部，按钮位 D 标记按场景转动，各家筹码与已投注额按场景实时显示（原型中 SB 0.5BB、BB 1BB）。
  • 左上 N / 20 进度；右上图标切换到该场景的 13×13 范围表；顶部右侧 Table 同为范围表入口（二者合并为一个入口）。
  • 底部三枚动作按钮，文案带金额：Fold / Call 2.5BB / Raise 7.5BB。加注尺度由场景固定，不需要玩家输入金额。
  • 已弃牌的对手位置变暗并移除手牌，开池者的下注筹码显示在其身前，让场景一眼可读。
  • 左上角 × 退出，弹确认框，退出即放弃本局成绩（已答手牌仍计入累计统计）。

6.4 训练中的范围表

13×13 网格，格子按加注频率填充，长按任一格显示该手牌的完整频率分布。右上角开关叠加个人热力图：用你在该格的历史错误率着色，把「我到底哪块记不住」变成一张图。

6.5 结算面

  • 大号 18 / 20 与评级词，下方 SHARE 与 CLOSE（与原型一致）。
  • INCORRECT 分组在前：每行显示两张牌面、你的选择、GTO 动作与频率条。
  • CORRECT 分组在后，同样显示频率，让你知道自己是蒙对还是打对。
  • 分享导出一张竖版图片，含得分、场景名、错题缩略图。

6.6 错题本

所有判错的手牌自动入库，按场景归档。支持一键「只练错题」，答对两次后自动移出。这是把训练闭环起来的关键，也是首页统计之外第二个回访理由。

6.7 设置

判定阈值、反馈模式、每局手数、是否按组合数加权、清空统计、导出与导入数据（JSON 文件，用于换机）。

07统计与存储

全部数据存在手机本地，不上传，不需要注册。

08技术方案

本机没有 Node 与 npm，也没有 Mac，方案要绕开这两个前提。

方案能装到 iPhone前置条件评价
A 单文件 Web AppSafari 添加到主屏幕无已确认采用。零依赖，改完即用，离线可跑
B React Native / ExpoTestFlight 或 App Store装 Node、Apple 开发者账号 99 美元/年、EAS 云构建体验最原生，链路最长
C Capacitor 套壳 A同上同上，但复用 A 的全部代码A 做完后的可选升级路径

推荐落地方式

  • 纯前端单页应用，原生 HTML + CSS + JavaScript，无框架无构建步骤，全部逻辑与 36 套范围数据内联在一个文件里。
  • 竖屏优先，按 iPhone 安全区适配（刘海与底部横条）。牌桌用 CSS 绘制，不依赖图片资源。
  • 加一份 Web App Manifest 与 Service Worker，让它以全屏无地址栏的形态启动，并可完全离线使用。
  • 代码分文件组织便于维护，交付时合并成一个可直接打开的 HTML。

09装到 iPhone

已确认走 GitHub Pages + 添加到主屏幕。落地分四步，最后一步在你的手机上完成。

步骤 1

产出 PWA 三件套

index.html 承载全部逻辑与范围数据，manifest.webmanifest 声明图标与全屏启动，sw.js 缓存全部资源实现离线。图标用 CSS 生成后导出，不依赖外部素材。

步骤 2

推到你的 GitHub 仓库

我在本地建好仓库结构并写好提交，你只需要提供仓库名。若你希望不公开，可用 private 仓库配合 Pages（需 GitHub Pro）或改用 Cloudflare Pages，两条都可行。

步骤 3

开启 Pages 拿到 https 链接

仓库设置里指定分支即可，几十秒后生效。Service Worker 必须在 https 下才注册，这是走托管而非本地文件的原因。

步骤 4

iPhone 上添加到主屏幕

用 Safari 打开链接（Chrome 不支持添加为独立 App），分享菜单选「添加到主屏幕」。之后点图标全屏启动，飞行模式下照常训练，成绩存在手机本地。
